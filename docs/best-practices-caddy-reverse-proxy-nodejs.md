"---\ntitle: Caddy Reverse Proxy Best Practices for Node.js Applications\ntags: [caddy, nodejs, reverse-proxy, performance, best-practices]\n---\n# PROBLEM
Caddy Reverse Proxy zu Node.js Anwendungen kann nach längerer Laufzeit Probleme machen: Verbindungen werden stale, Timeouts treten auf, statische Files werden nicht mehr geladen. Standard-Konfiguration ist für dauerhafte 24/7-Server oft nicht optimiert.\n\n# LÖSUNG
1. Statische Assets immer direkt über Caddy servieren (nicht durch Proxy)\n2. Node.js Keep-Alive-Timings korrekt aufeinander abstimmen\n3. Connection Pooling Limits setzen\n4. Health-Checks implementieren\n\n# CODE / COMMANDS\n## Empfohlene Caddyfile Struktur für Node.js\n```\n{\n    # Globales Logging aktivieren\n    log {\n        output file /var/log/caddy/access.log\n        format json\n    }\n}\n\nexample.com {\n    # Statische Dateien direkt servieren (Performance & Stabilität)\n    handle /static/* {\n        file_server {\n            root /var/www/app/public/static\n        }\n    }\n    handle /uploads/* {\n        file_server {\n            root /var/www/app/uploads\n        }\n    }\n    handle /public/* {\n        file_server {\n            root /var/www/app/public\n        }\n    }\n    \n    # API Routes werden durchgereicht\n    handle /api/* {\n        reverse_proxy localhost:3000 {\n            transport http {\n                dial_timeout 5s\n                response_header_timeout 10s\n                keepalive 90s\n                keepalive_idle_conns 20\n                max_idle_conns_per_host 100\n                max_response_header_bytes 8192\n            }\n            health_uri /health\n            health_interval 30s\n            health_timeout 5s\n            health_status 200\n        }\n    }\n    \n    # Alles andere an die App\n    handle {\n        reverse_proxy localhost:3000 {\n            transport http {\n                dial_timeout 5s\n                response_header_timeout 10s\n                keepalive 90s\n                keepalive_idle_conns 20\n                max_idle_conns_per_host 100\n            }\n            # Fail fast bei Problemen\n            fail_duration 10s\n            max_fails 3\n            unhealthy_latency 5s\n        }\n    }\n}\n```\n\n## Node.js Server Konfiguration (Express Beispiel)\n```javascript\nconst express = require('express');\nconst app = express();\nconst server = require('http').createServer(app);\n\n// Timeouts überschreiben (Standard sind 5s keepAlive, was zu kurz ist)\nserver.timeout = 120000; // 2 Minuten\nserver.keepAliveTimeout = 65000; // 65 Sekunden\nserver.headersTimeout = 66000; // Etwas länger als keepAliveTimeout\n\nconst PORT = 3000;\nserver.listen(PORT, () => {\n  console.log(`Server running on port ${PORT}`);\n});\n```\n\n## Systemd Service-File Optimierung\n```\n[Unit]\nDescription=Spikeball Application\nAfter=network.target caddy.service\n\n[Service]\nType=simple\nUser=nodejs\nWorkingDirectory=/var/www/spikeball\nExecStart=/usr/bin/node /var/www/spikeball/index.js\nRestart=always\nRestartSec=10\n\n# Timeouts erhöhen\nTimeoutStartSec=60\nTimeoutStopSec=60\n\n[Install]\nWantedBy=multi-user.target\n```\n\n## Health Check Endpoint in Node.js\n```javascript\napp.get('/health', (req, res) => {\n  // Additional checks if needed\n  res.status(200).json({ status: 'ok', timestamp: new Date().toISOString() });\n});\n```\n\n# SHELL OUTPUT / ERROR\nWarnungen zu \"connection reset by peer\" sollten nach diesen Änderungen verschwinden.\nPerformance-Tests zeigen stabilere Latenzen und kein Anstiegen von Timeouts über 24h.\n\n# WEITERE RESOURCEN\n- Caddy Reverse Proxy: https://caddyserver.com/docs/caddyfile/directives/reverse_proxy\n- Node.js HTTP Docs: https://nodejs.org/dist/latest-v20.x/docs/api/http.html\n- Connection Pooling: https://nodejs.org/en/docs/guides/backwards-compatibility/#stream\n- Systemd Service Config: man systemd.service\n---"
